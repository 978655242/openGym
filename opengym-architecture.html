1. 运行与数据架构

实线：常规请求/数据流；虚线：可选或设备特定路径。

客户端状态

  • useStore 持有可持久化训练状态；useUI 持有弹窗、sheet 等瞬态 UI。
  • 本地先写入；登录后以修订号 _rev 同步，409 返回服务器状态供客户端合并。
  • 访客模式不访问服务器；原生端额外镜像到私有文件，规避 WebView 存储被清理。

API 与安全

  • 无框架 node:http；METHOD /path 键值路由。
  • Passkey 为主认证；会话为 HMAC 签名 Cookie。配对原生端使用短时码换取 Bearer token。
  • Nginx 覆盖转发 IP 请求头，API 为推送端点阻断私网/回环 SSRF 目标。

数据主权

  • 用户状态按账户保存为扁平 JSON 文件，写入使用临时文件后 rename。
  • 需备份 ./data；媒体数据和身份凭据都在该宿主挂载卷。
  • MCP 直接读取同一目录，带文件监听与 mtime 回退，不经 HTTP，也不写数据。

3. 领域逻辑与模块边界

“决定下次训练内容或完成后如何回写”的逻辑集中在 frontend/src/lib，而非 React 视图层。

纯领域模块

  • progression.js：线性、Greyskull LP、双重递进、时间型策略。
  • finish-workout.js：完成会话回写重量、PR 和状态。
  • onerm.js、recovery.js、workout-model.js：1RM、疲劳恢复、会话状态机。

表现与交互层

  • views/：每屏一个入口；components/：图表、计时器、模态框和通用 UI。
  • sheets.jsx：跨视图的编辑/选择流程；locales/、instr/：多语言文本与动作说明。
  • HashRouter 使部署在子路径和静态托管时不依赖服务端页面路由。

可验证性

  • 纯逻辑与 Store 均有同目录 Vitest 测试；前端生产构建由 Vite 完成。
  • API 与 MCP 各有独立测试套件；CI 使用 Node 22 覆盖测试、locale 校验与镜像构建启动。
  • 训练规则变动应同步更新相邻 src/lib/*.test.js，而非只靠点击验证。
